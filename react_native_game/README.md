# Type-to-Run — React Native game (Expo)

The React Native version of the game, for iPhone, Android and web. It's the same game, backend and accounts as `flutter_game` and `react_game`. See the [root README](../README.md) for the game design and the [backend README](../backend/README.md) for the API.

Expo SDK 58 · React Native 0.88 · TypeScript · Zustand · AsyncStorage

## Run it

```bash
npm install
npx expo start
```

Start the backend first, in another terminal: `cd ../backend && npm run dev`.

- **Phone:** install **Expo Go**, put the phone on the same Wi-Fi as your Mac, and scan the QR code (iPhone: Camera app; Android: inside Expo Go).
- **Browser:** press `w`.
- **Android emulator:** press `a`. iPhone simulator (`i`) needs Xcode.

The app connects to the backend automatically, at port 3000 on the computer running `npx expo start`. The sign-in screen shows which server address it's using.

| Situation | What to do |
|---|---|
| "Can't reach the game server" on a phone | Phone and Mac must be on the same Wi-Fi; the backend must be running |
| School Wi-Fi blocks phone ↔ laptop | `npx expo start --tunnel`, and set `EXPO_PUBLIC_API_URL` in `.env` to a reachable backend URL |
| Play without a server | `EXPO_PUBLIC_OFFLINE=true` in `.env` |

After changing `.env`, restart with `npx expo start -c`.

## How it was converted from react_game

| | react_game (web) | react_native_game |
|---|---|---|
| Game rules `src/engine/*` | ✓ | **copied unchanged** |
| State machine `src/store/gameEngine.ts` (Zustand) | ✓ | **copied unchanged** |
| API client `src/repositories/*` | ✓ | **copied**; storage swapped to AsyncStorage |
| Types, content `src/types`, `src/data/seed.ts` | ✓ | **copied** (seed is regenerated by `npm run content` in react_game) |
| UI | HTML + Tailwind (`<div>`, `<span>`, `<button>`) | **rewritten** with React Native (`<View>`, `<Text>`, `<Pressable>`, `StyleSheet`) |
| Keyboard input | `window` keydown + hidden `<input>` | hidden `<TextInput>` (`src/components/TypingCapture.tsx`) |
| Saved login/progress | `localStorage` | `AsyncStorage` (`src/lib/storage.ts`) |
| Finding the backend | same host as the page, port 3000 | Expo's `hostUri` (your computer), port 3000 |

```
App.tsx                      root: storage → game init; mounts TypingCapture once
src/
  engine/ store/ types/      shared game logic (from react_game)
  repositories/              ApiRepository (backend) and LocalRepository (offline)
  lib/api.ts                 fetch client + automatic backend address
  lib/storage.ts             AsyncStorage, loaded once at startup
  components/                TypingCapture, TypingPrompt, TimerBar, CameraFeed, Panels
  screens/                   Auth, Menu, Run, Results
  __tests__/                 engine + game-flow tests (vitest)
```

**Typing across games:** `TypingCapture` is mounted once in `App.tsx` and takes focus back on every new prompt or phase, when the app returns to the foreground, and whenever it loses focus. So the next game accepts letters without tapping the screen.

## Walking camera

While you type a movement word, the camera moves as if you're walking: one bob per keystroke, a forward lurch down the corridor on each completed word, and a stumble on typos. During a chase it runs, with faster and bigger movement. The typed word stays steady on top so it's always readable. Each level has its own corridor: dorm doors, mansion fog and roots, buzzing hospital lights, and chapel water.

- Model (pure math, unit-tested): `src/engine/walkCamera.ts`
- Drawing: `src/components/CameraFeed.tsx` (react-native-svg)
- Flutter port: `flutter_game/lib/ui/widgets/walk_camera.dart`
